# ADR-0013: 답 없음 거절은 프롬프트 문구로 고치지 않는다

- 상태: 채택 (2026-10-19)
- 이슈: #94 (후속 #98)
- 결정한 사람: 소유자(miin-jun). 프롬프트 v2·측정 실행·B 1차 판정은 Claude
- 관련: [ADR-0010](0010-langgraph-agent.md) "미통과: 답 없음 거절 2/4"·"문제 → 원인 → 해결",
  [ADR-0006](0006-grounded-answer-refusal-and-citation.md)(거절 문구·번호 인용), 결과 [docs/eval/agent_refusal_v1_results.md](../eval/agent_refusal_v1_results.md)

## 맥락

- #22 개발 평가(`agent_dev_v1`)에서 답 없음 거절이 **2/4로 미통과**였다(기준 ≥ 3/4). n1·n2는 뜻은 거절이었지만 거절 문구 "문서에서 찾을 수 없음"으로 끝나지 않았고,
  **근거가 아닌 문장에 청크 번호를 붙였다**(n1 `[1]–[8]`, n2 `[1][4]`). 그래서 `is_refusal`이 거절로 세지 못하고, 출처 목록에 근거가 아닌 청크가 들어갔다
- 원인 추정(검증하지 않음, ADR-0010): 프롬프트 `agent_v1` 규칙 2("묻는 사실이 없으면 그 부분은 문서에서 찾지 못했다고 적는다")와 규칙 7("전혀 없으면 정확히 거절 문구만")이 겹친다

## 시도

- **`agent_v2`**: 규칙 2를 "묻는 사실이 여러 개이고 그중 일부만 찾았을 때"로 좁히고(못 찾은 사실은 번호 없이 "찾지 못했다"), 규칙 7에 "사업명·주제가 같은 청크가 있더라도
  하나도 찾지 못하면 정확히 거절 문구만, 청크 번호 없이"를 넣었다. `agent_v1.md`는 고치지 않고 새 파일로 만들었다
- **측정 전 기준 고정**: 세트 `agent_refusal_v1.jsonl`(A 답 없음 8 · B 일부만 찾음 3)·통과 기준·문항별 실패 조건·예상을 첫 실행 전에 커밋했다(56127b4).
  회귀(C)는 `agent_dev_v1` 답 있는 26문항. #22 세트는 거절 측정에 다시 쓰지 않았다
- **평가 질문 출처**: 질문 초안은 Claude 채팅, Claude Code가 RFP 원문(`data/parsed`·`data/chunks`)에서 "없는 사실"이 정말 없는지·"있는 사실"의 값을 확인, 사용자가 승인했다

## 결과 (2026-10-18, 버전당 1회)

| 구분 | 기준 (agent_v2) | agent_v1 | agent_v2 | 판정 |
|---|---|---|---|---|
| A 답 없음 (8) | 거절 ≥ 7/8, 거절한 답에 번호 0 | 3/8 | 3/8 | **미통과** |
| B 일부만 찾음 (3) | ≥ 2/3, 통째 거절 0 | — | 0/3 | **미통과** |
| C 회귀 (26) | v2 잘못 거절 ≤ v1 | 0 | 0 | 통과 |

- A: 두 버전 모두 a1·a7·a8만 거절했다. a2~a6은 두 버전 모두 뜻은 거절("찾지 못했습니다"·"명시되어 있지 않습니다")이지만 청크 번호를 붙였고, 대부분 주제가 같은 청크 설명을 덧붙였다 — #22 n1·n2와 같은 모양
- B: b1·b3은 있는 사실(기간)을 맞혔지만 못 찾은 사실의 문장에 청크 번호를 붙였다(b3은 보안 위약금을 예약 위약금으로 답하는 함정은 피함). b2는 원문에 "용역금액 99,000,000원"이 있는데
  예산을 "찾지 못했다"고 답했다 — 질문 "예산"과 원문 "용역금액"의 용어 차이로, 거절 규칙과는 별도 원인이다. b2도 못 찾은 사실(다크 모드) 문장에 번호 [1]을 붙였다
- LLM 162회(시험 1문항 포함) $0.100, 오류 0, agent_v2 37문항 p95 9.4초

**문구를 바꿔도 행동이 같았으므로 "규칙 2·7 충돌" 가설은 지지되지 않는다.** 모델은 주제가 같은 청크를 받으면 프롬프트 문구와 상관없이 "찾지 못했다"는 뜻에 청크 번호를 붙여 답했다.

## 결정

1. **기본 프롬프트는 `agent_v1`을 유지한다**(`agent/graph.py` `PROMPT_VERSION`). `agent_v2`는 거절·회귀 모두 v1과 같아 바꿀 이유가 없다.
   `agent_v2.md`와 `run_agent_dev --prompt agent_v2`는 이 측정의 재현용으로 남긴다
2. **답 없음 거절을 프롬프트 문구로 더 고치지 않는다.** 후속 #98은 판단과 문구를 나눈다: LLM은 질문 속 사실마다 found / not_found를 구조화 값으로 내고,
   모두 not_found면 **코드가** 정확한 거절 문구를 쓰고 출처를 비우며, 일부만 found면 not_found 사실의 번호를 코드가 뗀다
3. **이 세트(`agent_refusal_v1`)로 다시 재지 않는다.** 결과를 본 세트라, #98은 새 답 없음 세트로 검증한다(회귀는 `agent_dev_v1` 답 있는 26문항)

## 고려한 대안

| 대안 | 내용 | 판단 |
|---|---|---|
| 결과를 보고 기준 완화 | B를 뜻 기준(번호 위치를 따지지 않음)으로 보면 b1·b3이 통과해 2/3 | **채택 안 함** — 기준을 측정 전(56127b4)에 고정했는데 결과를 본 뒤 바꾸면 사후 완화다 (CLAUDE.md "평가 점수를 올리려고 평가 세트나 판정 기준을 바꾸지 않는다") |
| `agent_v2` 문구 추가 수정 | 규칙 7을 더 강하게 쓰고 같은 세트로 다시 잰다 | **채택 안 함** — 결과를 본 같은 세트를 다시 쓰면 그 11문항에 맞춘 과적합이 된다. 두 버전의 답 모양이 같아 문구 조정의 효과도 기대하기 어렵다 |
| `agent_v2`를 기본값으로 | 규칙이 더 명확하니 v2로 둔다 | **채택 안 함** — 측정상 개선이 없고, 아래 "한계"의 PMS 0건 위험을 C가 재지 못했다 |

## 한계

- **PMS 0건 결과에 규칙 7이 적용될 위험**: PMS 툴이 0건을 돌려주면 정답은 "0건"인데 "하나도 찾지 못하면 거절 문구만"이 적용될 수 있다. C에는 PMS 0건 문항이 없어 재지 못했다. #98의 구조화 출력 설계에서 "0건도 찾은 사실"로 다뤄야 한다
- **`is_refusal`은 완전 일치만 센다**: 뜻으로는 거절인 답(a2~a6)을 세지 않는다. 거절률은 문구 일치율이지 판단 정확도가 아니다
- 버전당 1회 실행, A 8문항이라 "문구를 바꿔도 같다"는 결론은 이 조건에서의 관찰이다

## 재검토

- #98에서 구조화 출력으로 바꾼 뒤 새 답 없음 세트로 거절률을 다시 잰다
- b2 같은 용어 차이(예산 ↔ 용역금액)로 있는 사실을 놓치는 문제는 검색·용어 쪽에서 따로 다룬다(#98 "알려진 다른 문제")
